# ADR-007 교체된 리프레시 토큰이 다시 오면 전부 폐기

## 배경

리프레시 토큰은 14일씩 살아 있어서 탈취되면 피해가 크다. 쓸 때마다 새 토큰으로 바꿔 주면(회전) 이전 토큰은 무효가 되지만, 공격자가 정상 클라이언트보다 먼저 탈취한 토큰을 쓰면 그때부터는 공격자가 새 토큰을 이어받게 된다.

## 검토한 방법

1. 회전만 적용 (이전 토큰은 그냥 무효)
2. 회전에 더해, 이미 교체된 토큰이 다시 오면 그 인가를 통째로 폐기 (RFC 9700에서 권장하는 방식)

## 결정

2번으로 했다.

## 결과

이미 교체된 토큰이 다시 들어왔다면 같은 토큰을 두 쪽이 갖고 있다는 뜻이다. 서버는 어느 쪽이 정상 사용자인지 알 수 없으니, 그 로그인에서 이어진 토큰(액세스, 리프레시, ID)을 전부 폐기한다. 정상 사용자는 다시 로그인하면 되고, 공격자는 더 이상 갱신하지 못한다.

구현은 이렇게 했다. 인가를 저장할 때 리프레시 토큰이 바뀌었으면 이전 토큰의 해시를 "교체됨" 키로 남겨 둔다. TTL은 이전 토큰의 남은 수명만큼이다. 나중에 토큰을 조회할 때 현재 유효한 토큰이 아닌데 교체됨 키에 있으면 재사용으로 판단한다.

재사용을 탐지하면 `[SECURITY]` 로그를 남긴다. 감사 이력 테이블에 쌓거나 알림을 보내는 건 아직 하지 않았다.

부작용도 있다. 네트워크 재시도 때문에 정상 클라이언트가 같은 갱신 요청을 두 번 보내면 그 사용자도 로그아웃된다. 짧은 유예 시간을 두는 방법도 생각해 봤지만, 그 시간 동안은 탈취된 토큰도 통과하게 되어서 두지 않았다. 대신 클라이언트 쪽에서 갱신 요청이 동시에 두 번 나가지 않게 막는 게 맞다고 봤다.

# ADR-007 회전된 리프레시 토큰이 재사용되면 인가 전체를 폐기

## 배경
리프레시 토큰은 수명이 길어(14일) 탈취되면 피해가 크다. 회전(사용할 때마다 새 토큰 발급)을 적용하면 이전 토큰은 무효가 되지만, 공격자가 정상 클라이언트보다 먼저 탈취한 토큰을 쓰면 공격자가 새 토큰 계보를 이어받게 된다.

## 선택지
1. 회전만 적용 (이전 토큰은 단순히 무효)
2. 회전 + 재사용 탐지 시 해당 인가 전체 폐기 (OAuth 2.0 Security BCP, RFC 9700 4.14절)

## 결정
2번.

## 결과
- 이미 회전된 토큰이 다시 들어왔다는 것은 같은 토큰을 두 주체가 갖고 있다는 뜻이다. 서버는 누가 정상인지 구분할 수 없으므로 그 로그인에서 이어진 토큰(액세스·리프레시·ID)을 모두 폐기한다. 정상 사용자는 다시 로그인하면 되고, 공격자는 더 이상 갱신할 수 없다.
- 구현: 인가를 저장할 때 리프레시 토큰이 바뀌었으면 이전 토큰의 해시를 "회전됨" 키로 남긴다(TTL = 이전 토큰의 남은 수명). 조회 시 활성 토큰이 아니고 회전됨 키에 있으면 재사용으로 판단한다.
- 재사용 탐지는 `[SECURITY]` 로그로 남긴다. 감사 이력 테이블과 알림 연동은 6주차 과제다.
- 부작용: 네트워크 재시도 등으로 정상 클라이언트가 같은 리프레시 요청을 두 번 보내면 로그아웃된다. 짧은 유예 시간을 두는 방법도 있으나, 유예 시간 동안은 탈취 토큰도 유효해지므로 두지 않는다. 클라이언트 SDK(5주차)가 갱신 요청을 직렬화해 중복 전송을 막는다.

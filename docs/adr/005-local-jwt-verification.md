# ADR-005 Introspection 대신 짧은 수명의 JWT와 로컬 검증

## 배경
각 서비스는 요청마다 액세스 토큰이 유효한지 확인해야 한다. 방법은 크게 두 가지다.

## 선택지
1. 불투명(opaque) 토큰 + 요청마다 인증 서버의 Introspection 엔드포인트 호출
2. 서명된 JWT + 각 서비스가 공개키(JWKS)로 직접 검증

## 결정
2번. 액세스 토큰 수명을 10분으로 짧게 두고, SDK가 로컬에서 검증한다.

## 결과
- 인증 서버가 모든 API 요청의 경로에서 빠진다. 그룹사 서비스 수만큼 늘어나는 호출이 인증 서버 부하와 장애 전파로 이어지지 않는다.
- SDK는 JWKS를 캐시(5분)하고, 모르는 kid가 오면 다시 조회하되 최소 간격(30초)을 둔다. 위조 토큰을 대량으로 보내도 인증 서버로 요청이 폭주하지 않는다.
- 인증 서버 장애 시에도 마지막으로 받은 공개키로 1시간 동안 계속 검증한다 (outage tolerance).
- 대가: 발급된 액세스 토큰은 만료 전까지 즉시 회수할 수 없다. 로그아웃이나 재사용 탐지로 인가를 폐기해도 이미 나간 액세스 토큰은 최대 10분 유효하다. 리프레시 토큰은 서버에서 즉시 폐기되므로 그 이후에는 갱신할 수 없다. 즉시 차단이 필요한 고위험 API는 Introspection을 추가로 쓰는 방식을 별도로 검토한다.

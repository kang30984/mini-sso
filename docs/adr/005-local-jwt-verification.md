# ADR-005 Introspection 대신 JWT를 서비스에서 직접 검증

## 배경

각 서비스는 요청이 올 때마다 액세스 토큰이 유효한지 확인해야 한다. 방법은 크게 두 가지다.

## 검토한 방법

1. 불투명 토큰을 쓰고, 요청마다 인증 서버의 Introspection 엔드포인트에 물어보기
2. 서명된 JWT를 쓰고, 각 서비스가 공개키(JWKS)로 직접 검증하기

## 결정

2번으로 했다. 액세스 토큰 수명을 10분으로 짧게 잡고, SDK가 서비스 안에서 검증한다.

## 결과

인증 서버가 모든 API 요청 경로에서 빠진다. 1번이었다면 그룹 서비스가 늘어날수록 인증 서버로 가는 호출도 늘고, 인증 서버 장애가 곧 전체 서비스 장애가 된다.

부하 테스트에서 이 차이가 실제로 보였다. 인증 서버가 Argon2 연산 때문에 거의 포화 상태였던 같은 환경에서도, SDK로 보호되는 API는 초당 3,900건 이상, 평균 12ms 정도로 처리됐다.

SDK는 공개키를 5분 동안 캐시한다. 캐시에 없는 키 ID가 오면 다시 받아오는데, 재조회 간격은 최소 30초로 제한했다. 위조 토큰을 대량으로 보내도 인증 서버로 요청이 몰리지 않게 하기 위해서다. 인증 서버가 잠깐 죽더라도 마지막으로 받은 공개키로 1시간까지는 계속 검증한다.

대가도 있다. 한번 나간 액세스 토큰은 만료될 때까지 회수할 수 없다. 로그아웃이나 재사용 탐지로 인가를 폐기해도 이미 발급된 액세스 토큰은 최대 10분 동안 유효하다. 리프레시 토큰은 서버에서 바로 폐기되니까 그 이후로는 갱신이 안 된다. 즉시 차단해야 하는 위험한 API라면 Introspection을 같이 쓰는 방법을 따로 검토해야 한다.

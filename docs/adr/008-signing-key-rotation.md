# ADR-008 서명 키 무중단 교체

## 배경
토큰 서명 키는 주기적으로, 그리고 유출이 의심될 때 즉시 교체할 수 있어야 한다. 교체 직후에도 이미 발급된 토큰과 각 서비스의 캐시된 공개키 때문에 검증이 실패하면 안 된다. 또한 4주차까지는 키를 기동 시 메모리에 생성해 재시작하면 모든 토큰이 무효가 되었다.

## 선택지
1. 키를 설정 파일·키스토어로 주입하고 교체는 배포로 처리
2. 키를 DB에 저장하고 상태(ACTIVE / RETIRING)로 생명주기를 관리, 관리 API로 교체

## 결정
2번.

- 교체하면 새 키가 즉시 ACTIVE가 되어 새 토큰에 서명하고, 이전 키는 RETIRING이 되어 보존 기간(1시간) 동안 JWKS에 계속 게시된다.
- 보존 기간은 이 키로 서명될 수 있는 토큰 중 가장 오래 사는 것(ID 토큰 30분)보다 길게 잡는다.
- 개인키는 AES-256-GCM으로 암호화해 저장한다. 마스터 키는 환경 변수로만 주입하며 기본값이 없다(없으면 기동 실패). kid를 AAD로 묶어 다른 키의 암호문으로 바꿔치기할 수 없다.

## 결과
- 서비스 쪽에서는 아무 작업 없이 교체가 반영된다. 새 kid의 토큰이 오면 SDK가 JWKS를 다시 받는다 (KeyRotationIT로 검증).
- 서명용 키 집합(활성 키 1개)과 게시용 키 집합(활성 + 보존 중)을 분리했다. 서명기에 여러 키를 주면 어떤 키로 서명할지 모호해 실패하기 때문이다.
- 인스턴스마다 키를 30초 캐시한다. 여러 인스턴스 환경에서는 교체 후 최대 30초 동안 인스턴스마다 서명 키가 다를 수 있으나, 두 키가 모두 게시되어 있어 검증에는 문제가 없다.
- 남은 개선점: 새 키를 먼저 게시만 하고 일정 시간 뒤 서명에 쓰는 "사전 게시" 단계를 두면, 다른 인스턴스의 JWKS 캐시가 갱신되기 전에 새 키 토큰이 나가는 상황까지 없앨 수 있다. 정기 교체 스케줄러와 함께 6주차 이후 과제로 남긴다.

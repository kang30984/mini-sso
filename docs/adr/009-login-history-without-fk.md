# ADR-009 로그인 이력 테이블에 계정 FK를 두지 않음

## 배경
`login_history`는 모든 로그인 시도마다 한 건씩 쌓이는 append-only 테이블이다. 존재하지 않는 계정에 대한 시도도 무차별 대입 탐지를 위해 기록해야 한다.

## 선택지
1. `account_id`에 FK를 걸고, 존재하지 않는 계정 시도는 별도 테이블에 기록
2. FK 없이 `account_id`를 NULL 허용으로 두고 인덱스만 생성

## 결정
2번.

## 결과
- 로그인마다 발생하는 INSERT에서 FK 검사와 부모 행 잠금(InnoDB의 공유 잠금)이 사라진다. 로그인 트래픽이 몰릴 때 계정 행 갱신과의 잠금 경합을 줄인다.
- 이력은 감사 목적이므로 계정이 삭제되어도 남아 있어야 한다. FK가 있으면 계정 삭제가 막히거나 CASCADE로 이력이 지워진다.
- 정합성(존재하는 계정 ID만 저장)은 DB가 아닌 애플리케이션이 보장한다. 이력은 `LoginService`에서만 생성되므로 관리 범위가 좁다.
- 사용자가 입력한 로그인 ID 원문을 저장하므로, ID 칸에 비밀번호를 잘못 입력한 경우가 기록될 수 있다. 길이를 100자로 제한하고, 보존 기간 정책(예: 1년 후 파기)은 6주차에 정한다.

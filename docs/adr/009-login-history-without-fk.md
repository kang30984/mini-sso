# ADR-009 로그인 이력 테이블에 FK를 두지 않기

## 배경

`login_history`는 로그인 시도가 있을 때마다 한 줄씩 쌓이기만 하는 테이블이다. 무차별 대입을 찾아내려면 존재하지 않는 계정으로 시도한 기록도 남겨야 한다.

## 검토한 방법

1. `account_id`에 FK를 걸고, 없는 계정으로 시도한 기록은 다른 테이블에 남기기
2. FK 없이 `account_id`를 NULL 허용으로 두고 인덱스만 만들기

## 결정

2번으로 했다.

## 결과

로그인할 때마다 일어나는 INSERT에서 FK 검사와 부모 행에 대한 공유 잠금이 빠진다. 로그인이 몰릴 때 계정 행을 갱신하는 쪽과 잠금이 부딪히는 일이 줄어든다.

이력은 감사용이라 계정이 지워져도 남아 있어야 한다. FK가 있으면 계정 삭제가 막히거나, CASCADE를 걸면 이력이 같이 지워진다.

정합성은 DB 대신 애플리케이션이 맞춘다. 이력은 `LoginService`에서만 만들기 때문에 신경 쓸 범위가 좁다.

사용자가 입력한 로그인 ID를 그대로 저장하다 보니, ID 칸에 비밀번호를 잘못 넣은 경우까지 기록될 수 있다. 그래서 길이를 100자로 제한했다. 이력을 얼마나 보관할지는 아직 정하지 않았다.

# ADR-012 검증된 클라이언트 시크릿 캐시

## 배경

부하 테스트에서 토큰 갱신 요청이 평균 823ms 걸렸다. 같은 실행에서 JWKS 조회는 5.6ms, Argon2 연산이 없는 인가 요청 단계는 150ms 정도였다.

토큰 갱신에는 사용자 비밀번호 비교가 없다. 그런데 토큰 엔드포인트는 요청마다 클라이언트를 인증하고, 클라이언트 시크릿이 Argon2로 저장되어 있어서 토큰을 요청할 때마다 Argon2 비교가 한 번씩 일어난다. Argon2는 메모리를 16MB 정도 쓰도록 일부러 느리게 만든 알고리즘이다. 서비스들이 10분마다 토큰을 갱신한다고 하면 이 비용이 사용자 수만큼 쌓인다. 게다가 Argon2가 CPU를 잡고 있다 보니 다른 요청까지 같이 느려졌다.

## 검토한 방법

1. 클라이언트 시크릿을 SHA-256 같은 빠른 해시로 저장
2. Argon2 설정값을 낮추기
3. 저장은 Argon2 그대로 두고, 검증에 성공한 시크릿만 잠깐 기억하기

## 결정

3번으로 했다. Spring Authorization Server가 클라이언트 인증에 쓰는 `PasswordEncoder`만 캐시 데코레이터(`VerifiedSecretCachingPasswordEncoder`)로 감쌌다.

1번은 시크릿이 충분히 무작위일 때만 안전하다. 지금은 관리자가 시크릿을 정해서 넣기 때문에 그 전제를 보장할 수 없다. 2번은 계정 비밀번호 보호 수준까지 같이 낮아진다.

## 결과

DB가 유출됐을 때의 보호 수준은 그대로다. 저장된 해시는 여전히 Argon2다. 틀린 시크릿은 캐시하지 않으니 무차별 대입을 하면 매번 Argon2 비용을 그대로 치른다.

캐시 키는 SHA-256(입력한 시크릿 + 저장된 해시)로 만들었다. 메모리에 시크릿 원문이 남지 않고, 시크릿을 바꾸면 저장된 해시가 달라지니 이전 캐시는 자동으로 쓸모가 없어진다. 항목 수는 클라이언트 수만큼이고 TTL은 10분이다.

계정 비밀번호는 이 캐시를 거치지 않게 했다. `Argon2PasswordHasher`는 `PasswordEncoder` 빈을 주입받지 않고, 캐시가 없는 인코더를 직접 만들어 쓴다.

효과는 같은 커밋에서 캐시만 끄고 켜서 부하 테스트로 비교했다. 토큰 갱신 처리량이 초당 23.8회에서 289.1회로 약 12배 늘었고, 평균 지연은 800ms에서 67ms로 줄었다. CPU 경합이 줄어든 덕에 캐시와 직접 관계없는 로그인 흐름 처리량도 9.7회에서 18.2회로 늘었다.

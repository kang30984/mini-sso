# ADR-010 동의 화면 생략, PKCE는 모든 클라이언트에 강제

## 배경

mini-sso에 등록되는 클라이언트는 모두 같은 그룹의 사내 서비스라고 가정했다. 그리고 모두 서버에서 돌아가는 앱이라 client_secret을 안전하게 보관할 수 있는 기밀 클라이언트다.

## 검토한 방법

- 동의 화면: 보여줄지, 생략할지
- PKCE: 공개 클라이언트에만 적용할지, 모든 클라이언트에 적용할지

## 결정

동의 화면은 생략하고(`requireAuthorizationConsent(false)`), PKCE는 모든 클라이언트에 필수로 적용했다. 방식은 `S256`만 허용한다(`requireProofKey(true)`).

## 결과

사용자는 "이 앱이 내 정보에 접근하려고 합니다" 같은 화면 없이 한 번 로그인으로 사내 서비스를 오갈 수 있다. 외부 서비스를 클라이언트로 받게 되면 클라이언트별로 동의 화면을 켤 수 있게 설정을 나누면 된다.

기밀 클라이언트에도 PKCE를 쓰는 이유는 인가 코드가 새는 경로가 생각보다 많기 때문이다. 브라우저 기록, 서버 로그, Referer 헤더 같은 곳으로 코드가 나가도 code_verifier가 없으면 토큰으로 바꿀 수 없다. OAuth 2.1 초안과 RFC 9700에서 권장하는 방향과도 같다.

클라이언트 쪽에는 일이 하나 늘어난다. Spring Security OAuth2 Client는 기밀 클라이언트에 PKCE를 기본으로 붙이지 않아서, `OAuth2AuthorizationRequestCustomizers.withPkce()`를 직접 설정해야 한다. 샘플 앱 A에 그 예가 있다.

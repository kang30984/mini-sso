# ADR-001 헥사고날 구조를 Gradle 모듈로 나누기

## 배경

인증 서버는 한번 만들면 오래 쓰는 시스템이다. 그동안 저장소(MySQL, Redis)나 프로토콜 구현, 알림 방식 같은 기술 요소는 바뀔 수 있지만, 계정 잠금이나 세션 정책 같은 규칙은 잘 바뀌지 않는다. 두 가지가 한 코드에 섞여 있으면 라이브러리 하나 올리거나 저장소를 바꿀 때 도메인 규칙까지 손대게 된다.

## 검토한 방법

1. 단일 모듈에 controller / service / repository 계층 패키지
2. 단일 모듈에 헥사고날 패키지
3. 헥사고날 구조를 Gradle 모듈로 분리

## 결정

3번으로 했다. 도메인, 애플리케이션, 어댑터를 각각 모듈로 나누고 의존 방향은 `bootstrap → adapter → application → domain` 한쪽으로만 흐르게 했다.

## 결과

패키지만 나누면 규칙을 어겨도 컴파일이 된다. 모듈로 나누면 도메인 모듈에는 Spring이 클래스패스에 없으니 잘못된 의존이 처음부터 불가능하다.

모듈이 늘어나면서 빌드 설정이 복잡해지는 문제는 Convention Plugin(`build-logic`)으로 공통 설정을 한곳에 모아서 해결했다. 같은 모듈 안의 패키지 의존이나 어댑터끼리의 의존은 컴파일러가 막아 주지 않기 때문에 ArchUnit 테스트로 따로 확인한다.

도메인 모델과 JPA 엔티티를 분리했기 때문에 둘 사이의 매핑 코드가 생겼다. 대신 도메인 클래스가 기본 생성자나 open 클래스 같은 JPA 제약에 끌려가지 않는다. 이 정도 매핑 코드는 감수할 만하다고 봤다.

모듈로 나눠 둔 효과는 실제로 한 번 확인했다. 앱 전체를 띄우면 통과하던 테스트가 영속성 모듈만 단독으로 테스트할 때 실패했는데, 다른 모듈이 우연히 채워 주던 의존성이 빠져 있었던 것이다 ([트러블슈팅 2번](../troubleshooting.md)).
